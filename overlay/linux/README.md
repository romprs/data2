# Screen watermark overlay — Linux/X11 prototype (Этап 0-1)

Полноэкранное click-through окно с тайловым водяным знаком (имя
пользователя), поверх всех приложений. Часть модуля "экранный оверлей"
из [`PROJECT_PLAN.md`](../../PROJECT_PLAN.md) (раздел 4.2).

## Зависимости

Базовые (`text`/`account`, весь функционал кроме режима `dots`), пакеты apt (Ubuntu/Debian):

```bash
sudo apt-get install -y python3-pyqt5 python3-xlib
```

Для режима `watermark_type: "dots"` дополнительно нужен `cryptography`
(рендер) и `numpy`+`Pillow` (только для `decode_dots.py`, не для самого
оверлея).

Всё вместе, через pip (см. `requirements.txt`):

```bash
pip install -r requirements.txt
```

> Если система ставит PyQt5 под другую версию Python3, чем та, что
> запускает скрипт (несовпадение `ABI`, ошибка `No module named
> 'PyQt5.sip'`), поставьте пакет через pip для нужного интерпретатора:
> `pip install --force-reinstall PyQt5`.

## Запуск

```bash
python3 watermark_overlay.py
```

Параметры (все опциональны):

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--text` | `{user}` | Шаблон текста. Доступны `{user}`, `{host}`, `{time}` |
| `--opacity` | `45` | Alpha-канал текста, 0-255 |
| `--font-size` | `18` | Размер шрифта |
| `--angle` | `-30` | Угол наклона тайлов, градусы |
| `--spacing` | `80` | Отступ между тайлами, px |
| `--mode` | `always` | `always` — всегда видим, `app_list` — только пока открыто приложение из `--apps`, `none` — не запускаться / выключить |
| `--apps` | `""` | Список подстрок `WM_CLASS` через запятую, напр. `soffice,acroread,firefox` |
| `--watermark-type` | `text` | `text` — шаблон `--text`, `account` — всегда учётная запись ОС, `dots` — зашифрованный точечный код (см. ниже) |
| `--dot-size` | `3` | Размер точки в px (только `--watermark-type dots`) |
| `--key-file` | `/etc/watermark-overlay/watermark.key` | Файл AES-256 ключа (только `--watermark-type dots`) |

Пример: `python3 watermark_overlay.py --text "{user} · {time}" --opacity 60`

Пример условного показа: `python3 watermark_overlay.py --mode app_list --apps "soffice,acroread" --watermark-type account`

## Управление прозрачностью и остальными настройками (конфиг-файл)

Вместо CLI-флагов настройки можно хранить в JSON-файле — это то, чем
удобно управлять при запуске как службы (см. ниже), не трогая unit-файл.
Порядок приоритета (следующий переопределяет предыдущий):

1. встроенные значения по умолчанию;
2. `/etc/watermark-overlay/config.json` — системный дефолт (опционально,
   для централизованной настройки администратором);
3. `~/.config/watermark-overlay/config.json` — пользовательский;
4. `--config PATH`, если указан явно (тогда 2 и 3 игнорируются);
5. соответствующие CLI-флаги (`--opacity` и т.д.), если переданы.

Формат — см. [`config.example.json`](config.example.json):

```json
{
  "text": "{user}",
  "opacity": 45,
  "font_size": 18,
  "angle": -30.0,
  "spacing": 80,
  "watermark_type": "text",
  "mode": "always",
  "apps": []
}
```

### Справочник полей

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `text` | строка | `"{user}"` | Шаблон текста знака. Используется только если `watermark_type: "text"`. Подстановки: `{user}` — логин, `{host}` — имя машины, `{time}` — текущие дата/время. Пример: `"{user} · {time}"` |
| `opacity` | целое, 0–255 | `45` | Прозрачность текста (альфа-канал). `0` — знак невидим, `255` — максимально контрастный |
| `font_size` | целое | `18` | Размер шрифта в pt |
| `angle` | число | `-30.0` | Угол наклона тайлов, градусы |
| `spacing` | целое | `80` | Отступ между повторами текста, px |
| `watermark_type` | `"text"` \| `"account"` \| `"dots"` | `"text"` | `"text"` — рендерится шаблон из `text`. `"account"` — `text` игнорируется, всегда показывается фиксированная учётная запись ОС: полное имя (GECOS из `/etc/passwd`), если задано, иначе `логин@хост`. `"dots"` — ни `text`, ни читаемого текста вообще: логин+время шифруются AES-256-GCM и рисуются точечным узором (см. раздел ["watermark_type: dots"](#watermark_type-dots--зашифрованный-точечный-код-вместо-читаемого-текста) ниже). **Важно:** это значение по умолчанию самого скрипта/`HARD_DEFAULTS` при запуске совсем без конфига — RPM-пакет с версии 0.6.0 ставит другой дефолт в `/etc/watermark-overlay/config.json` (`"dots"`), см. `packaging/redos/README.md` |
| `dot_size` | целое | `3` | Диаметр точки в px. Используется только если `watermark_type: "dots"` |
| `key_file` | строка или `null` | `null` (→ `/etc/watermark-overlay/watermark.key`) | Путь к AES-256 ключу. Используется только если `watermark_type: "dots"` |
| `mode` | `"always"` \| `"app_list"` \| `"none"` | `"always"` | `"always"` — знак виден постоянно. `"app_list"` — знак виден, только пока открыто хотя бы одно окно из списка `apps`. `"none"` — оверлей полностью выключен: если задано при запуске, процесс завершается сразу, не открывая ни одного окна; если переключить в этот режим у уже запущенного процесса — он сам завершится в течение секунды (кнопка-выключатель через общий конфиг) |
| `apps` | массив строк | `[]` | Подстроки для поиска в `WM_CLASS` открытых окон (без учёта регистра). Работает только при `mode: "app_list"`. Пример: `["soffice", "acroread", "firefox"]`. Подробнее про `WM_CLASS` — в разделе ["Когда показывать знак"](#когда-показывать-знак-mode-apps-и-что-показывать-watermark_type) ниже |

Указывать нужно только те поля, которые хотите переопределить —
остальные возьмутся из значений по умолчанию/предыдущего уровня
конфига (см. приоритет выше). Невалидный JSON в файле молча
игнорируется (в stderr идёт предупреждение вида `watermark-overlay:
skipping bad config ...`), применяются значения с других уровней.

Создать пользовательский конфиг:

```bash
mkdir -p ~/.config/watermark-overlay
cp config.example.json ~/.config/watermark-overlay/config.json
```

**Изменения применяются на лету**, без перезапуска процесса: оверлей
следит за конфиг-файлом (`QFileSystemWatcher`) и перерисовывается
в течение примерно секунды после сохранения файла. Чтобы сделать знак
заметнее/незаметнее — просто отредактируйте `opacity` (0-255) в
конфиге и сохраните.

**Переключение между `text`/`account`/`dots` работает так же на лету**
— это не отдельная функция, а тот же общий механизм: `watermark_type`
в конфиге ничем не отличается от любого другого поля. Проверено на
реальной РЕД ОС VM 2026-08-18: заменил `/etc/watermark-overlay/config.json`
с `"watermark_type": "text"` на `"watermark_type": "dots"` у уже
запущенного процесса (PID не менялся) — видимый на весь экран текст
сменился на еле заметную точечную сетку примерно за секунду, без
перезапуска и без разрыва сессии пользователя. Так же можно переключать
и при самом запуске — флагом `--watermark-type` (см. таблицу выше) или
через `--config PATH` с готовым файлом, например
[`config.example.dots.json`](config.example.dots.json).

## Когда показывать знак (`mode`, `apps`) и что показывать (`watermark_type`)

**`mode`** — когда виден знак:

| Значение | Поведение |
|---|---|
| `"always"` (по умолчанию) | знак виден всегда, поверх всех окон |
| `"app_list"` | знак виден, только пока открыто хотя бы одно окно из списка `apps` — независимо от того, в фокусе оно или нет |
| `"none"` | оверлей выключен целиком (не просто скрыт) — см. ниже |

**`apps`** — список подстрок, которые ищутся (без учёта регистра) в
`WM_CLASS` открытых окон. Используется только при `mode: "app_list"`.
`WM_CLASS` — это техническое имя приложения в X11 (не заголовок окна);
узнать его для конкретного приложения:

```bash
xprop WM_CLASS   # затем кликнуть на окно приложения
```

Типичные значения: `soffice`/`libreoffice` (LibreOffice), `acroread`,
`okular`, `evince` (PDF), `firefox`, `chromium`, `code` (VS Code).
Проверка на совпадение — по подстроке, так что `"office"` поймает и
`libreoffice-writer`, и `libreoffice-calc`.

**`watermark_type`** — что именно написано на знаке:

| Значение | Поведение |
|---|---|
| `"text"` (по умолчанию) | рендерится шаблон из `text` (`{user}`/`{host}`/`{time}`) |
| `"account"` | шаблон `text` игнорируется, всегда рендерится учётная запись ОС: полное имя из GECOS (`/etc/passwd`), если задано, иначе `user@host` — этот вариант нельзя случайно настроить так, чтобы он перестал показывать личность пользователя |
| `"dots"` | никакого читаемого текста — вместо него зашифрованный точечный код (см. раздел ["Зашифрованный точечный код"](#watermark_type-dots--зашифрованный-точечный-код-вместо-читаемого-текста) ниже) |

Пример конфига «знак только при работе с офисными/PDF-приложениями и
браузером, показывать учётную запись» — см.
[`config.example.app_list.json`](config.example.app_list.json).

Проверка активности пересчитывается по опросу (~2 раза/сек через
`_NET_CLIENT_LIST`, нужен `python-xlib` и WM с поддержкой EWMH — так же,
как для "прилипания" к рабочим столам выше). Если `python-xlib`
недоступен или нет подключения к X — модуль **показывает знак**
(fail-open), а не скрывает его молча.

**`mode: "none"` — полное выключение (кнопка-выключатель через общий конфиг):**

- Если `none` указан **уже при запуске** процесса (например, в
  `/etc/watermark-overlay/config.json` до входа пользователя в
  систему) — процесс завершается немедленно, не создавая ни одного
  окна и не открывая соединение с X-сервером: это буквально "демон не
  запустится", а не "запустился и молча ничего не показывает".
- Если конфиг **переключили в `none`, пока оверлей уже работает**
  (например, администратор отредактировал общий `/etc`-файл как
  аварийный выключатель для всех пользователей сразу) — уже
  запущенный процесс сам завершается в течение ~1 секунды (тот же
  механизм живого обновления, что и для прозрачности).
- Чтобы включить обратно — верните `"mode"` в `"always"` или
  `"app_list"` в конфиге и запустите оверлей заново (автоматически он
  не поднимется сам, т.к. процесс уже завершился — либо через
  `watermark-overlay &`, либо перезайдя в сессию, если настроен
  автозапуск).

Пример конфига-выключателя — [`config.example.disabled.json`](config.example.disabled.json).

## `watermark_type: "dots"` — зашифрованный точечный код вместо читаемого текста

### Зачем

Читаемый текст на экране решает задачу «сдержать/напомнить», но не
задачу «надёжно установить, кто сделал фото/скриншот»: любой видимый
регулярно повторяющийся узор — хоть буквы, хоть простые точки без
шифрования — снимается стандартной обработкой изображений (не только
ИИ-инструментами), если известен период повтора. Режим `dots` вместо
этого:
- не показывает никакого читаемого текста (не отвлекает, не считывается взглядом);
- кодирует логин пользователя и время в точечный узор, **зашифрованный AES-256-GCM**;
- расшифровывается только офлайн, отдельным инструментом
  (`decode_dots.py`) и тем же ключом — не человеком «на глаз».

Это смещает цель с *сдерживания* на *установление личности постфактум*
по фото/скриншоту утечки — см. обсуждение компромиссов в
[`PROJECT_PLAN.md`](../../PROJECT_PLAN.md).

### Формат

Полезная нагрузка (28 байт: 24 байта логина + 4 байта времени) шифруется
AES-256-GCM (свежий случайный nonce при каждой перерисовке — сама
зашифрованная последовательность байт меняется каждый кадр, даже если
данные внутри те же) — получается 56 байт = 448 бит. Каждый бит — это
"нарисовать точку" (1) или "не рисовать" (0), точки укладываются в
решётку 16×28 и повторяются по экрану с тем же отступом `spacing`, что
и текстовый режим. Подробности формата — в
[`dotcode.py`](dotcode.py), это общий модуль для рендера и расшифровки.
Пример конфига — [`config.example.dots.json`](config.example.dots.json).

### Ключ шифрования

Нужен общий 32-байтный ключ — по умолчанию `/etc/watermark-overlay/watermark.key`,
путь настраивается полем `key_file`. Создать:

```bash
sudo mkdir -p /etc/watermark-overlay
sudo openssl rand -out /etc/watermark-overlay/watermark.key 32
```

(в RPM-пакете это делается автоматически при установке, если файла ещё нет — см. `packaging/redos/README.md`).

Без валидного ключа режим `dots` **ничего не рисует** (не падает, но и
не показывает знак) — в лог идёт предупреждение с готовой командой для
генерации ключа.

> **Честно про хранение ключа**: с версии RPM-пакета 0.5.0 файл ключа
> — 0640, группа `watermark-overlay` (созданная и наполненная локальными
> пользователями с UID 1000-59999 автоматически при установке), а не
> 0644 всем подряд. Это сужает круг тех, кто может его прочитать, до
> тех, у кого и так есть легитимная причина (интерактивные графические
> пользователи — им ключ нужен, чтобы шифровать свою же метку), вместо
> вообще любой локальной учётки, включая служебные. Это **не** закрывает
> исходную проблему: технически подкованный пользователь по-прежнему
> может найти ключ на диске (он и так состоит в этой группе, иначе
> оверлей не смог бы для него ничего зашифровать) и расшифровать чужие
> метки или подделать свою. Правильное решение — доверенный
> привилегированный компонент, который шифрует вместо самого процесса
> пользователя (или разовые ключи от сервера политик, раздел 4.4
> плана) — в прототип это пока не входит. Локальная группа также не
> распространяется на AD/SSO-учётки — открытый вопрос, раздел 11 плана.

### Расшифровка (для расследования утечки)

```bash
python3 decode_dots.py screenshot.png --key-file /etc/watermark-overlay/watermark.key
```

Пример вывода:
```
Watermark decoded:
  user:      ivanov
  timestamp: 2026-08-17T14:15:53+03:00
  found at:  (17, 17) in screenshot.png
```

Инструмент перебирает все возможные положения точечной решётки в
пределах одного периода тайла (не весь снимок целиком, но и не только
позицию (0,0)) — поэтому декодирует и **произвольно обрезанный**
скриншот (например, скриншот только окна документа, а не всего
экрана), если в нём помещается хотя бы один полный тайл (при
`dot_size=3` это область примерно 80×140 px). Неверный ключ или
испорченные данные не дают "похожий, но неверный" ответ — за счёт
AES-GCM это либо точный правильный результат, либо явный отказ
`No watermark decoded`.

**Производительность**: полный перебор по всему изображению — не
мгновенная операция. На скриншоте 1024×768 худший случай (знака нет
вообще) — около 20 секунд, на 1920×1080 — около минуты (тестировалось
в этой среде разработки, не оптимизировалось дальше; это инструмент
для разового расследования, а не для реального времени).

**Проверено:** рендер → скриншот (полный и произвольно обрезанный) →
расшифровка, под Xvfb, автотест
[`../../tests/linux/run_dots_test.sh`](../../tests/linux/run_dots_test.sh).

**Не проверено (важное ограничение):** расшифровка настоящего **фото
с телефона**, а не скриншота. Фото добавляет то, чего в скриншоте нет:
перспективные искажения от угла съёмки, муар от несовпадения сетки
пикселей экрана и матрицы камеры, блики/неравномерное освещение, шум и
сжатие. Текущий декодер рассчитан именно на пиксель-в-пиксель точные
скриншоты — устойчивость к реальному фото требует отдельной работы
(геометрическая коррекция перспективы, помехоустойчивое кодирование
сильнее одной лишь проверки AES-GCM tag, подбор размера точки под
муар) и тестирования на реальных снимках, что в этой среде разработки
сделать невозможно. Пожалуйста, проверьте на реальном телефоне и
пришлите результат — от этого зависит, стоит ли вкладываться в
доработку под фото.

## Как это работает

- Окно создаётся с флагами `FramelessWindowHint | WindowStaysOnTopHint |
  Tool | X11BypassWindowManagerHint | WindowTransparentForInput |
  WindowDoesNotAcceptFocus` — оно всегда поверх остальных окон, не
  показывается в панели задач и **не получает ввод** (клики и клавиатура
  проходят к нижележащему приложению).
- `WA_TranslucentBackground` + отрисовка текста с низким alpha — знак не
  перекрывает читаемость контента.
- На каждый подключённый монитор (`QApplication.screens()`) создаётся
  своё окно-оверлей; при подключении/отключении монитора список
  синхронизируется автоматически (`screenAdded`/`screenRemoved`).
- Дополнительно (если доступен `python-xlib`) на окно навешиваются EWMH
  хинты `_NET_WM_STATE_STICKY` + `_NET_WM_DESKTOP=-1`, чтобы оно
  оставалось поверх при переключении виртуальных рабочих столов —
  это то, что штатные флаги Qt не всегда покрывают на всех WM.

## Ограничения прототипа (см. раздел 8 плана)

- Требует композитор/WM с поддержкой EWMH для полной устойчивости к
  переключению рабочих столов; без `python-xlib` (или на WM без EWMH)
  окно всё равно рисуется и остаётся поверх на текущем столе, но не
  "прилипает" ко всем столам.
- **Wayland не поддерживается** — X11-специфичные флаги
  (`X11BypassWindowManagerHint`) не действуют на Wayland-композиторах;
  нужна отдельная реализация через `wlr-layer-shell` (см. раздел 4.2
  плана, риск №2 в разделе 8).
- Это только экранный/скриншотный/фото-слой. Печать этим модулем **не**
  покрывается — для неё отдельный модуль перехвата печати (раздел 4.3
  плана, Этап 2), т.к. печать не идёт через композитор рабочего стола.
- `mode: "app_list"` определяет совпадение по `WM_CLASS` любого открытого
  окна (не только окна в фокусе), но это опрос раз в ~500мс, а не
  событие — при открытии/закрытии приложения знак появляется/исчезает
  с задержкой до полусекунды, а не мгновенно.
- Anti-tamper здесь минимальный: RPM-пакет (с версии 0.5.0) оборачивает
  запуск в bash-цикл перезапуска (`watermark-overlay.wrapper`) — `kill`
  или падение процесса перезапускают его через ~2с, `mode: "none"` в
  конфиге по-прежнему уважается как осознанное отключение (процесс не
  перезапускается). Это реальный, проверенный на живой RED OS VM фикс:
  до 0.5.0 пакет ставил только `/etc/xdg/autostart`, без какого-либо
  перезапуска — пример systemd-юнита в `systemd/` существовал в
  репозитории, но RPM его не устанавливал, поэтому `kill <pid>` просто
  насовсем убивал процесс до следующего входа в систему. Но и цикл
  перезапуска — не полноценный anti-tamper: он выполняется от имени
  того же пользователя, что и оверлей, так что его тоже можно убить
  (например, убив весь процесс-дерево или отключив автозапуск в своём
  `~/.config/autostart`) — полноценная защита (раздел 6 плана) требует
  системной службы с правами, недоступными текущему пользователю, что
  выходит за рамки Этапа 0-1.
- Потребление памяти: около 60 МБ RSS на процесс (по одному процессу
  на пользователя) — это в основном база PyQt5/Python, а не что-то
  специфичное для оверлея. Изначально было ~115 МБ из-за ненужной
  инициализации софтверного OpenGL (Mesa/`libLLVM`) — отключено через
  `QT_XCB_GL_INTEGRATION=none`, задаётся из самого скрипта. На
  терминальном сервере с десятками одновременных сессий 60 МБ на
  пользователя всё ещё заметно суммируются — для такого сценария
  единственный способ уменьшить дальше — переписать оверлей без Qt
  (см. раздел 7 плана про пересмотр стека для промышленной версии).

## Автозапуск (systemd user service)

Юнит запускает `watermark_overlay.py` без флагов — все настройки берутся
из конфиг-файла (см. выше), путь к репозиторию задан относительно `%h`
(домашняя директория) — поправьте `ExecStart` в
[`systemd/watermark-overlay.service`](systemd/watermark-overlay.service),
если склонировали в другое место.

```bash
mkdir -p ~/.config/systemd/user
cp systemd/watermark-overlay.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now watermark-overlay.service
```

Проверить статус / логи:

```bash
systemctl --user status watermark-overlay.service
journalctl --user -u watermark-overlay.service -f
```

Изменить прозрачность у запущенной как служба копии — просто
отредактировать `~/.config/watermark-overlay/config.json`, перезапуск
не требуется (см. "Управление прозрачностью" выше).

> На некоторых DE user-юниты с `WantedBy=graphical-session.target` не
> подхватывают DISPLAY/XAUTHORITY автоматически. Если служба падает с
> ошибкой подключения к X-серверу — добавьте в `[Service]`:
> `Environment=DISPLAY=:0` (или актуальный вывод `echo $DISPLAY` в вашей
> сессии).

## Тесты

Headless smoke-тест (поднимает Xvfb + openbox + xterm, проверяет что
знак реально рисуется на экране, покрывает весь экран и прозрачен для

```bash
sudo apt-get install -y xvfb openbox xterm xdotool imagemagick
pip install -r requirements.txt
bash ../../tests/linux/run_smoke_test.sh       # always-on watermark: render/full-screen/click-through
bash ../../tests/linux/run_app_list_test.sh    # mode=app_list: hidden -> shown -> hidden
bash ../../tests/linux/run_dots_test.sh        # watermark_type=dots: render -> screenshot -> decode
```
